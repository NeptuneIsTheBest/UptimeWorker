# 架构与代码组织

[English](../architecture.md) | [简体中文](architecture.md)

[返回 README](../../README.zh-CN.md) · [开发与维护](development.md)

UptimeWorker 在同一个 Cloudflare Worker 上提供 API、定时检测和前端静态资源，D1 保存监控配置、检测历史与事件。代码先按运行环境分层，再按功能组织。

## 依赖与接口边界

- `shared` 使用纯 TypeScript 和 Web 标准能力，不依赖 React、Hono、D1 或运行环境模块。业务类型和常量放在对应功能中，聚合响应类型引用各功能类型。
- 前端由 `app` 组合功能，功能使用公共组件、hooks 和请求客户端。状态页组合监控卡片与事件列表；页面刷新和业务表单状态分别管理，使刷新可以保留未保存的输入。
- Worker 由 `app` 注册 HTTP 中间件和功能路由。路由处理请求、校验和响应；repository 负责数据库访问。公开聚合位于 `status`，监控检测快照可以读取设置模块提供的查询与解码能力。
- 模块直接导入实际定义文件。新增共用能力放到所属的较低层，保持依赖方向一致，避免循环。

页面地址由 [App](../../src/web/app/App.tsx) 选择，HTTP 接口由各功能的 `routes.ts` 注册。公开接口契约见 [API 参考](api.md)，共享类型可从 [shared](../../src/shared/) 按功能查找。

## 请求与检测流程

HTTP 请求先应用安全响应头、请求大小限制和 Access 鉴权，再进入功能路由。只有明确列出的公开 GET 接口使用缓存；管理接口及错误响应不缓存。管理页通过同一个鉴权入口返回 SPA 资源，保持原导航地址。

公开监控查询只选择展示字段，不加载探测配置。状态聚合将日统计按监控一次分组，全部监控共享一次生成的 90 天 UTC 日期序列。公开事件借助部分索引合并全部未结束事件与最近 20 条已结束事件，节点事件从有索引的关联记录开始筛选。事件、关联与完整进展在同一事务批次中读取，再一次分组组装。

调度申请 D1 租约，在同一 `DB.batch` 中读取设置和已启用的到期监控；查询使用 `monitors_due` 索引，按 `next_check_at, id` 排序并应用配置的批量限制。即时测试复用快照读取与探测，仅针对指定节点；读取失败时不执行检测或生成样本。

共享性能模块为调度器和前端估算提供校验、平台基准与预算规则。推迟项保留到期时间，内部异常安排下一分钟重试并保留状态与历史，两者均不生成失败样本。240 秒租约防止重叠执行。预算计算见[调度与容量模型](#调度与容量模型)。

结果写入时复核监控版本、启用状态和租约。检测明细采用 `(monitor_id, scheduled_at)` 复合主键的 `WITHOUT ROWID` 表，省去额外唯一索引并防止重复统计；时间索引支持历史读取和按同一复合键执行的有界清理。触发器在样本写入事务中按当前规则更新统计与自动事件。事件写入通过版本检查和私有写入令牌，保证并发修改下的状态、关联、进展和静默区间一致。

`worker/features/ordering` 在物化快照中校验完整成员集合、原版本与原序号，以单条 UPDATE 原子提交目标顺序。服务排序独立于监控配置版本，保留执行中的检测结果。前端共享 `useReorder` 和 `SortControls`，由 `useRemote.suspend` 在排序期间中止旧读取并暂停刷新，保存后合并响应并恢复。

未分组的位置保存在 `monitor_groups` 的 `__ungrouped__` 系统记录中，节点归属仍为 null。接口单独返回 `ungrouped` 元数据，`shared/groups/ordering` 按数据库排序规则将其与普通分组合并。

每轮清理最多 500 条过期检测明细、100 条过期日汇总和 100 条过期静默记录。保留期限与聚合规则见[统计与保留策略](#统计与保留策略)。

事件关联通过单个 JSON 参数及 `json_each` 校验，避免超过 D1 的 100 个绑定参数限制。成功且有结果的调度通常共 4 次 D1 调用：申请租约、快照、结果、清理与完成。完成时已释放租约，仅未完成的运行执行兜底释放。`DB.batch` 无论包含多少语句均计为一次；调用次数不代表 D1 行用量，容量规划还需考虑索引、触发器、CPU 与清理积压。

前端复用各语言的格式化器，缓存历史条及只依赖数据的统计汇总，并按组索引监控。已挂载组件共享 1 秒和 15 秒节奏的展示时钟；页面隐藏时停止计时，恢复可见时立即校正显示，API 刷新使用全局页面刷新设置，缓存期限见 [API 参考](api.md#全局设置)。

## 调度与容量模型

Cron 每分钟运行。候选批次按到期时间顺序，在并发、HTTP 请求和墙钟时间预算内启动检测。推迟项保留到期时间，留待下一轮处理。重叠调用和已完成的分钟时间窗会跳过，错过的时间窗不补跑。探测内部异常将该监控推迟到下一分钟，不生成样本。监控总数没有固定上限。

调度器与估算共用 `createProbeBudget`。每个 HTTP 检测为初始请求和最多三次重定向预留四次子请求，即使没有重定向也使用完整预算。Free 每轮预算 50 次，最多启动 12 项 HTTP 检测；Paid 为 10,000 次。TCP 不占 HTTP 请求预算。启动前，剩余墙钟时间须覆盖该项完整超时和五秒结果保存时间。数据库延迟可能延长整轮耗时；运行超过一分钟时，后续 Cron 会因租约而跳过。

估算仅包含启用监控，假设均按计划完成：

| 指标               | 计算方法                                   |
| ------------------ | ------------------------------------------ |
| 每日检测量         | `Σ(1440 / intervalMinutes)`                |
| 平均每分钟检测需求 | 每日检测量 / 1440                          |
| 每日 HTTP 请求量   | 每日 HTTP 检测量的 1–4 倍，不含 TCP        |
| 七天明细量         | 每日检测量 × 7                             |
| 每日基础写入下限   | 每日检测量 × 3：检测明细、日汇总、监控状态 |

手动测试不计入模型。基础写入不包含索引、事件状态转换、清理及其他 API 请求。D1 提示将此下限与 Free 每日额度的 80% 比较；Paid 将每日下限乘以 30，再与每月包含用量的 80% 比较。计费和容量判断使用账户实际指标。

峰值模拟令全部启用监控在零时刻到期，同到期时间按 ID 排序，假设每项耗尽超时，将获准检测分配给最早空闲的并发位置。模拟不计配置读取延迟。候选耗时上界为 `ceil(候选数 / 并发) × 最大超时`，容量占比在 80–100% 时显示接近上限，超过 100% 时显示超出预算。峰值推迟项可以分轮处理；平均需求超过每分钟批量时，无法维持目标检测频率。

## 统计与保留策略

- 单节点 30 日可用率为包含今天的最近 30 个 UTC 日内，成功检测数除以完成检测数。整体可用率先汇总全部节点的检测次数再计算。缺失样本和暂停区间不增加检测数，不按持续时间加权；维护期间的检测正常计入。
- 总状态与汇总指标覆盖全站，不受展示筛选影响。获取数据失败优先，其次为未结束故障、服务异常或数据过期，再次为已经开始且尚未完成的维护。未来维护及已结束事件不影响总状态。正常服务数量依据检测状态，平均响应时间取当前正常服务的最近非空耗时。
- 首次检测前为未知，停用为暂停，超过两个配置周期未更新为过期。浏览器在两次 API 刷新之间也会更新过期状态。基础设施故障不生成成功或失败样本。
- HTTP 耗时包含重定向和最终响应处理；关键词校验的正文读取计入同一超时与耗时测量。TCP 只测连接建立，不执行 TLS、数据库查询或应用协议校验。执行位置由 Cloudflare 调度，不提供固定城市或多地区探针。
- 时间戳为 UTC 毫秒，日汇总使用 UTC 日期，检测时间按浏览器时区展示。保留七天检测明细和包含今天的 90 个 UTC 日汇总；详情响应包含最近 24 小时全部明细。分批清理在停机后可能需要多轮完成。
- 编辑监控保留历史。检测参数变化重置当前状态、检测计划和未发布故障计时；名称或分组变化保留这些值。删除监控级联删除明细与日汇总，保留事件记录。

## 事件生命周期

首次失败的定时检测启动故障计时，后续失败检测在达到阈值后发布一条自动事件。例如间隔十分钟、阈值五分钟，最早在第二次失败检测时发布。首次成功检测清除未发布计时，或追加恢复进展并完成已有自动事件。阈值为零时停止新事件发布，已有事件仍可自动恢复。

维护在 `[startsAt, endsAt)` 内静默新发自动事件，从发布时起生效；检测与可用率统计继续。提前完成结束该窗口的静默，其他重叠有效窗口继续生效。关联的未结束手动故障同样静默自动事件。静默结束后从首次失败检测重新计时，包括整个维护窗口都发生在两次检测之间的情况。

暂停、修改检测参数或超过两个周期的数据缺口会重置未发布计时。未知、过期状态和即时测试不发布事件；暂停或编辑不会完成已发布事件。删除关联节点会追加自动 `Stopped` 进展并停止跟踪。

手动维护超过计划结束时间仍保持开放，直到追加 `Completed`；手动故障通过 `Resolved` 结束。完成状态与静默变化原子提交。已结束事件可追加 `Updated` 说明，保持已结束状态。编辑手动事件更新首次发布记录，不保存编辑审计历史。事件长期保留。

自动事件标题保存发布时的节点名称及固定后缀 ` 服务异常`，节点改名后仍用已保存名称展示。自动正文按阶段翻译：首次 `Investigating`、恢复 `Resolved`、停止跟踪 `Stopped`。管理员追加的进展使用 `source: manual`，原样展示。API 字段及阶段取值见[分组与事件](api.md#分组与事件)。

## 前端样式与新增功能

[样式入口](../../src/web/styles/index.css) 显式加载基础、通用组件、布局、各功能样式和可访问性规则。功能样式与对应组件放在一起，媒体查询留在所属样式文件中。涉及跨文件覆盖时需检查选择器优先级和加载顺序，并对照桌面与移动端画面。

新增功能时，先确定共享契约，再添加 Worker 路由与数据访问、前端组件及对应功能测试。跨功能聚合放在页面或聚合服务中，通用 HTTP 行为放在 `http`，不要让基础组件承担业务数据读取。

数据库变更及验证命令见[开发与维护](development.md)。接口变化同步更新 API 参考，操作变化同步更新配置或部署指南。

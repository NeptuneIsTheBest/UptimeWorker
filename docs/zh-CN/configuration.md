## 基本配置

在「监控管理」中选择「新增监控」，填写名称和公网目标地址后保存。

| 设置          | 选项                                               |
| ------------- | -------------------------------------------------- |
| 检测类型      | HTTP/HTTPS 或 TCP 端口                             |
| 检测间隔      | 1–60 的整数分钟，默认 1 分钟                       |
| 超时时间      | 1–30 秒                                            |
| HTTP 方法     | GET / HEAD / POST / PUT / PATCH / DELETE / OPTIONS |
| HTTP 成功条件 | 响应符合期望状态码范围及已配置的关键词             |
| TCP 成功条件  | 成功建立目标端口连接                               |

使用「测试连接」立即检查已保存的配置。定时检测更新状态和历史，即时测试不改变这两项数据。所有请求方法均按配置的间隔重复执行。

HTTP 使用公网 URL。TCP 使用公网域名或 IP，内网地址、Cloudflare IP 和端口 25 不可用；经过 Cloudflare 代理的服务使用 HTTP 检测。

在监控列表中可暂停或恢复检测。修改检测参数后，当前状态等待下一轮检测更新；修改名称或分组保留状态。删除监控会永久删除其检测历史。

## 页面自动刷新

在「全局设置 → 页面自动刷新」设置公开页和管理页的刷新间隔。可选关闭、15 / 30 / 60 秒，或自定义 5–3600 的整数秒，默认 30 秒。

刷新保留筛选条件和未保存的输入。关闭自动刷新时使用「立即刷新」；在其他页面重新开启后，已停刷的页面也需手动刷新一次。「更新于」表示页面获取数据的时间，「最近检测」表示服务实际检测时间。

## 服务器分组与事件

通过「分组管理」创建、重命名、排序或删除分组，在监控编辑器中分配节点。拖动手柄或使用上移、下移按钮调整分组和服务顺序，修改自动保存。服务在组内排序，新建或换组的服务追加到末尾。删除分组会将其中的服务移至未分组。

首页支持搜索、状态和分组筛选，以及分组折叠，与后台共用展示顺序。未分组也可排序；浏览器分别记忆首页和后台的折叠偏好。

在「事件」页签填写标题、正文并关联节点，发布故障或计划维护。使用「追加进展」记录处理过程；选择「维护完成」或「故障恢复」会同时结束手动事件。点击事件标题可打开、分享完整时间线。

管理页顶部的「进行中与计划事件」展示全部未结束故障和维护，包括超过计划时间仍未完成的维护；下方的「历史事件」按每页 20 条分页。两个分区均按最近更新时间倒序排列。翻阅或刷新历史时，全部未结束事件仍在顶部展示；发布、编辑或追加进展后返回最新一页历史。

发布事件时，故障正文默认填入「正在排查」的说明，维护正文默认填入「计划维护」的说明；追加进展时默认填入「进展更新」的说明。切换事件类型或进展阶段时，空白和未修改的自动说明会随之更新，手动修改的非空内容会保留。点击「使用阶段说明」可替换当前正文，并恢复自动跟随。编辑已有事件时保留原正文，该按钮使用事件类型对应的初始阶段说明。自动说明随界面语言切换，手动内容和保存后的正文保持原文；清空后直接提交仍须通过非空校验。

维护时间按浏览器时区填写，结束时手动确认完成。计划维护期间继续检测和统计可用率，暂停新发自动故障事件。首页展示全部未结束事件和最近 20 条已结束事件，节点详情展示关联事件。

在「全局设置 → 离线自动事件」中设置连续失败的发布阈值，默认 5 分钟，支持 1–1440 分钟，设为 0 关闭自动发布。自动事件随成功检测确认恢复，也可手动追加处理说明，结束后可删除。

删除监控后，事件及节点名称仍会保留，进行中的自动事件停止跟踪。事件计时和静默规则详见[架构文档](architecture.md#事件生命周期)。

## HTTP 高级配置

在监控编辑器中展开「高级配置」：

- **自定义请求头**：填写 Authorization、Cookie、API Key 等，合计最多 8 KiB。携带凭据时使用最终检测地址。
- **请求体**：选择文本或 JSON，最多 16 KiB。自动设置 Content-Type，也可通过自定义请求头覆盖。GET 和 HEAD 不发送请求体。
- **响应校验**：每行一个关键词，每组最多 20 个，每个最多 256 字符。包含项须全部出现，排除项须全部不出现，可选择忽略大小写。两组留空时只检查状态码，HEAD 也只检查状态码。

检测最多跟随三次重定向。带请求体且会跨源跳转时，请直接配置最终地址。参数校验、重定向和检测错误见 [API 参考](api.md#http-请求与响应规则)。

## Cloudflare WAF 放行

对于你管理的 Cloudflare 站点，配置 Skip 规则和共享密钥：

1. 在各 HTTP 监控中开启「WAF 放行」并保存，使用目标站点的完整域名和 HTTPS 检测地址。
2. 打开「全局设置」，生成或输入 32–256 位密钥，保存前先复制；保存后显示为「已配置」。
3. 展开「Cloudflare Skip 规则配置」，复制完整规则。使用模板时，将 `<YOUR_TOKEN>` 替换为已保存的密钥。
4. 在目标站点的 **Security rules** 中创建自定义规则，填写表达式，选择 **Skip** 和需要跳过的功能，放在相关拦截规则之前。普通 Bot Fight Mode 需要单独配置，Skip 无法跳过它；参见 [Cloudflare 支持范围](https://developers.cloudflare.com/waf/custom-rules/skip/options/)。
5. 保存目标站点规则，开启全局 WAF 开关并保存设置。执行「测试连接」，在 Cloudflare Security Events 中确认规则匹配。

密钥留空保留原值。更换密钥或监控域名后，同步更新目标站点规则。密钥校验及发送规则见 [API 参考](api.md#waf-凭据)。

## 检测、统计与保留策略

状态页展示当前健康状态、30 日可用率和 90 日历史条。可用率按检测成功率统计；每日汇总使用 UTC，单次检测时间按浏览器时区显示。

节点详情展示最近 24 小时的响应时间及全部检测记录。检测明细保留 7 天，每日汇总保留 90 天，事件长期保存。首次检测前显示「等待检测」，超过两个检测周期未更新时显示「数据过期」。

聚合公式与状态规则见[统计与保留策略](architecture.md#统计与保留策略)。

## 性能设置与容量估算

在「性能」页签调整调度设置。估算随当前输入更新，保存后从下一轮检测生效。

| 设置           | 默认值 | 范围        |
| -------------- | ------ | ----------- |
| Workers 套餐   | Free   | Free / Paid |
| 检测并发数     | 4      | 1–6         |
| 每轮最大检测数 | 10     | 1–500       |
| 每轮时间预算   | 50 秒  | 40–180 秒   |

套餐选择与 Cloudflare 订阅保持一致，此设置用于确定应用预算；订阅在 Cloudflare 管理。

面板估算检测次数、HTTP 请求量、保留样本量和基础写入下限，并模拟全部启用服务同时到期的情况。若检测经常推迟，可提高批量或时间预算，或延长检测间隔。实际 Worker CPU 和 D1 用量在 Cloudflare 查看。

计算方法见[调度与容量模型](architecture.md#调度与容量模型)，日志和测量方法见[运行观测](development.md#运行观测)。
